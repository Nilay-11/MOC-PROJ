MOC Mini Project / Theory of Computation

Catching phishing URLs with finite automata.

A URL is just a string over an alphabet Σ. We describe suspicious patterns as regular languages, compile each one from a regular expression into a minimal DFA, and let those machines read the URL one character at a time. Their verdicts, plus a few structural rules, add up to an explainable risk score.

Theoretical background

The theory each part of the detector relies on.

Each card states a definition or theorem from automata theory and the place in the detector where it is used.

Alphabet, strings, languages

Σ = {a…z, 0…9, - . _ ~ : / ? # [ ] @ ! $ & ' ( ) * + , ; = %, ⊥}
w ∈ Σ*,  L ⊆ Σ*

An alphabet is a finite set of symbols, a string is a finite sequence of them, and a language is any set of strings. ⊥ stands for every character outside the URL character set.

In the project: the URL is the input string w. Each pattern, e.g. “contains login”, is a language Llogin = Σ*·login·Σ*.

Regular expressions

r ::= a | ε | r₁r₂ | r₁ + r₂ | r*
L(.*login.*) = Σ* {login} Σ*

Regular expressions denote languages built from symbols with union, concatenation and Kleene star. Our parser also accepts the shorthands +, ?, [0-9] and . (any symbol of Σ).

In the project: all 13 patterns, from .*@.* to [0-9]+\.[0-9]+\.[0-9]+\.[0-9]+, are written as regular expressions.

Deterministic finite automaton

M = (Q, Σ, δ, q₀, F)
δ : Q × Σ → Q

A finite set of states, an alphabet, a total transition function, a start state and a set of accepting states. Exactly one move is defined for every state and symbol, so a run never branches.

In the project: the DFA class stores Q, the symbol classes of Σ, a δ table, q₀ and F, and a run is a table lookup per character.

Extended transition function

δ̂(q, ε) = q
δ̂(q, wa) = δ(δ̂(q, w), a)
L(M) = { w ∈ Σ* | δ̂(q₀, w) ∈ F }

δ̂ applies δ along a whole string. A string is accepted when the state reached after the last symbol is accepting.

In the project: DFA.run() computes δ̂ and returns every intermediate state. That trace is what the simulator animates.

Nondeterministic finite automaton (NFA)

N = (Q, Σ, δ, q₀, F)
δ : Q × (Σ ∪ {ε}) → 𝒫(Q)

An NFA may have several moves, or none, for the same symbol, and may move on ε without reading input. It accepts if some path ends in F. NFAs are easy to build from regular expressions.

In the project: each regular expression is first converted into an NFA with at most 2|r| states (18 states for .*login.*).

Kleene's theorem

regular expressions ≡ NFA ≡ DFA

A language is denoted by a regular expression if and only if some finite automaton accepts it. This is why a pattern written as a regex can always be checked by a DFA.

In the project: it guarantees that every pattern has a DFA. We verified each compiled DFA against Python's re on 20,000 random strings plus every short string.

Subset construction (Rabin–Scott)

QD ⊆ 𝒫(QN),  qD0 = ε-closure(q₀)
δD(S, a) = ε-closure(⋃q∈S δN(q, a))

Each DFA state is a set of NFA states. In the worst case this needs 2|QN| states, but only reachable subsets are generated, and the empty set becomes the dead state.

In the project: 18 NFA states for login produce only 13 reachable subsets, not 2¹⁸ = 262,144.

Myhill–Nerode and minimisation

x ≡L y ⇔ ∀z: xz ∈ L ⇔ yz ∈ L
|Qmin| = index of ≡L

A language is regular if and only if ≡L has finitely many classes, and the minimal DFA has exactly one state per class. It is unique up to renaming of states.

In the project: Moore's refinement shrinks the login DFA from 13 to 6 states, q₀…q₅, which is the diagram drawn in our proposal.

Closure properties

L₁ ∪ L₂,  L₁ ∩ L₂,  L̄,  L₁L₂,  L* are regular

Regular languages are closed under the Boolean operations, concatenation and star. Union can be realised as a product automaton or by compiling the union regex.

In the project: the nine keyword DFAs (64 states in total) merge into one 44-state DFA for the union. We keep them separate so each verdict can be reported and weighted on its own.

Pumping lemma: what DFAs cannot do

∃p ∀w ∈ L, |w| ≥ p: w = xyz,
|xy| ≤ p, |y| ≥ 1, ∀i ≥ 0: xyⁱz ∈ L

Some languages are not regular. For example {aⁿbⁿ}, balanced brackets, and “the link text equals the real host” all need unbounded memory.

In the project: this is why counts and comparisons (URL length, number of labels) run as structural rules in ordinary code, outside the automata.

Proposed system

Four modules, one pipeline.

The automata are only responsible for pattern recognition. Parsing, counting rules and scoring are separate modules, so the detector is not presented as a single formal language.

MODULE 1

URL parser

Normalises case and splits the URL into scheme, userinfo, host, subdomain, domain, port, path, query and fragment.

parse_url()
MODULE 2

MOC automata engine

Compiles each regex through regex → NFA → DFA → minimal DFA and runs the resulting DFA on its URL component.

compile_regex(), DFA.run()
MODULE 3

Feature detector

Collects DFA verdicts, applies the structural rules and adds up the weights into a score and a class.

analyse(), classify()

Correctness against Python re

Each minimal DFA and re.fullmatch judged the same strings: 20,000 random strings, plus every string up to length L built from one character per symbol class.

Linear-time scanning

A DFA does one table lookup per character, so time grows linearly with input length: O(n), independent of the pattern.

Discussion

What the detector can and cannot tell you.

Limitations

  • Keywords are evidence, not proof. accounts.google.com/signin scores 2 and is flagged although it is legitimate.
  • Clean-looking URLs pass. A shortened link such as bit.ly/3xYzAbc contains no pattern and scores 0.
  • No memory beyond finite states. Comparing displayed text with the real host, or counting without a bound, is not regular.
  • Thresholds are project rules. The weights and the 0–1 / 2–3 / ≥ 4 bands are choices we made, not properties of automata.

Future scope

  • Trusted-domain allowlist and percent-decoding before the automata run.
  • One product DFA whose accepting states record which keywords were found, in the style of Aho–Corasick.
  • Homoglyph patterns such as paypa1 or rn written in place of m, as further regular languages.
  • Threat-intelligence feeds and a comparison with machine-learning detectors on a public dataset.
